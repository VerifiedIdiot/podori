# 독립 실행형 함정 예제

[English](README.en.md)

비공개 애플리케이션 소스를 복사하지 않고 새로 작성한 합성 예제입니다.
테스트는 이 예제만 검증하며, 이전 애플리케이션 실험을 재현하지 않습니다.
Node.js 22 이상과 기본 제공 모듈만 사용합니다.
외부 패키지 설치, 인증 정보, 외부 네트워크 요청이 필요하지 않습니다.
함정은 기본적으로 비활성화합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `server.mjs` | HTTP 서버와 합성 정상 엔드포인트를 제공합니다. |
| `trap.mjs` | 격리한 미끼, 레지스트리, 자원 한도, 이벤트를 관리합니다. |
| `test/http.test.mjs` | 내부 루프백에서 실제 HTTP 요청으로 검증합니다. |
| `test-sandbox.sh` | 자원과 네트워크를 제한한 Docker 테스트를 실행합니다. |
| `package.json` | 테스트와 시작 명령을 정의합니다. |

## 격리 환경에서 테스트합니다

저장소 루트에서 다음 명령을 실행합니다.

```sh
cd examples/trap
sh test-sandbox.sh
```

스크립트에 명시한 이미지가 로컬 Docker에 있어야 합니다.
스크립트는 이미지를 내려받거나 패키지를 설치하지 않습니다.
이미지가 없으면 명령이 실패합니다.
승인된 네트워크 환경에서 다음 명령으로 이미지를 준비한 뒤 테스트를 다시 실행합니다.

```sh
docker pull node@sha256:9bef0ef1e268f60627da9ba7d7605e8831d5b56ad07487d24d1aa386336d1944
```

테스트는 컨테이너 내부 루프백의 임시 포트에서 실제 HTTP 서버를 실행합니다.
호스트 포트를 공개하지 않으며, 외부 네트워크를 차단합니다.
예제 디렉터리만 읽기 전용으로 마운트합니다.
인증 정보와 Docker 소켓을 마운트하지 않습니다.

컨테이너는 읽기 전용 루트 파일시스템과 UID 65534를 사용합니다.
Linux capability를 모두 제거하고 `no-new-privileges`를 적용합니다.
CPU 1개, 메모리 128 MiB, 프로세스 64개, 임시 파일시스템 16 MiB로 제한합니다.
컨테이너 내부 테스트 명령에 30초 제한을 적용하며, 종료 후 컨테이너를 제거합니다.
검증한 Docker 런타임은 `runc`입니다.

예상 결과는 테스트 22개 통과, 실패·취소·건너뛰기 0개입니다.
종료 코드가 0이 아니면 검증 실패로 처리합니다.

### 직접 실행합니다

승인한 로컬 환경에서만 다음 명령을 사용합니다.

```sh
npm test
# 같은 테스트 러너를 직접 실행합니다.
node --test --test-concurrency=1 test/*.test.mjs
```

직접 실행할 때는 Docker 격리가 적용되지 않습니다.

## 로컬 데모를 수동으로 실행합니다

다음 명령은 호스트 루프백 리스너를 엽니다.
격리 테스트 명령은 호스트 리스너를 열지 않습니다.

```sh
npm start
```

다른 터미널에서 정상 엔드포인트와 비활성 미끼를 확인합니다.

```sh
curl -i http://127.0.0.1:8080/api/tiles
curl -i http://127.0.0.1:8080/decoy/export
```

정상 엔드포인트는 HTTP 200과 `{"tiles":["sample"]}`을 반환합니다.
비활성 미끼는 HTTP 404를 반환합니다.

Ctrl+C로 프로세스를 종료합니다.
로컬 데모에서만 다음과 같이 함정을 활성화합니다.

```sh
TRAP_ENABLED=1 npm start
```

다른 터미널에서 합성 확인 요청을 전송합니다.

```sh
node --input-type=module <<'NODE'
const origin = 'http://127.0.0.1:8080';
const issued = await fetch(`${origin}/decoy/export`).then(r => r.json());
const proof = { artifact: issued.artifact, challenge: issued.challenge };
for (let attempt = 0; attempt < 2; attempt++) {
  const response = await fetch(`${origin}/decoy/export/confirm`, {
    method: 'POST',
    headers: { origin, 'content-type': 'application/json' },
    body: JSON.stringify(proof),
  });
  console.log(response.status, await response.text());
}
NODE
```

첫 확인 요청은 HTTP 200과 `{"export":"synthetic","rows":[]}`을 반환합니다.
동일한 증명을 다시 제출하면 HTTP 409를 반환합니다.
실제 내보내기 기능이나 실제 데이터는 없습니다.

Ctrl+C로 프로세스를 종료합니다.
함정을 비활성화하려면 `TRAP_ENABLED=1` 없이 다시 시작합니다.
프로세스 내부의 `trap.disable()`도 대기 중인 함정 본문 처리를 중단하고 함정 상태를 삭제합니다.
이 메서드를 호출한 후에도 정상 엔드포인트는 동작합니다.

## 이벤트 판정 규칙

`GET /decoy/export`는 독립적인 난수 기반 아티팩트와 챌린지를 발급합니다.
서버는 원문 대신 해시와 합성 메타데이터를 크기가 제한된 레지스트리에 저장합니다.
GET, HEAD, 페이지 제공만으로 관찰 이벤트를 기록하지 않습니다.

`POST /decoy/export/confirm`는 만료 전에 등록된 아티팩트와 챌린지가 정확히 일치해야 합니다.
서버는 이벤트를 저장하기 전에 증명을 소진합니다.
동시 요청이나 재전송은 동일한 증명으로 이벤트를 두 번 생성하지 못합니다.
이벤트 저장에 실패하면 증명을 소진한 상태에서 HTTP 503을 반환합니다.

운영자 origin은 `http://127.0.0.1:8080`으로 고정합니다.
미끼 요청의 Host 헤더는 고정 호스트와 일치해야 합니다.
확인 요청은 Origin 헤더도 검사하며, 충돌하는 fetch 메타데이터를 거부합니다.
요청 헤더로 신뢰할 origin을 결정하지 않습니다.
Origin 검사는 인증이 아니며, 브라우저가 아닌 클라이언트는 헤더를 위조할 수 있습니다.

이벤트는 합성 아티팩트의 사용만 나타내며, 악의적인 사람의 신원을 입증하지 않습니다.
복사한 유효 증명도 해당 아티팩트에 대한 관찰만 생성합니다.
IP, 사용자, 세션, 쿠키, 증명 원문, 제출한 신원 정보는 이벤트에 저장하지 않습니다.
자동 제재나 IP 차단은 수행하지 않습니다.
이벤트 또는 진단 정보를 조회하는 HTTP 엔드포인트는 제공하지 않습니다.

이벤트는 프로세스 메모리에만 저장합니다.
`storeEvent` 옵션은 동기식 테스트 오류 주입용이며, 외부 저장소 연동 인터페이스가 아닙니다.
이 옵션에 비동기 저장소나 외부 서비스를 연결하지 않습니다.
테스트는 저장 예외를 주입하고 실패 응답을 확인합니다.

## 기본 자원 한도

모든 한도는 단일 프로세스에 적용합니다.
운영자가 제공하는 테스트 옵션으로 한도를 줄일 수 있습니다.
HTTP 입력으로 한도를 변경할 수는 없습니다.

| 자원 | 한도 |
|---|---|
| 함정 요청 본문 | 512바이트 |
| 함정 본문 처리 시간 | 500밀리초 |
| 동시 함정 본문 처리 | 4개 |
| 함정 요청 수락 | 고정된 60초 구간마다 60개 |
| 미사용 아티팩트 | 16개 |
| 챌린지 유효 기간 | 10초 |
| 이벤트 | 32개 |
| 이벤트 보존 기간 | 60초 |
| 만료 정리 | 1초마다 수행합니다. |
| HTTP 헤더 크기 | 4096바이트 |
| 서버 연결 | 32개 |
| 연결당 요청 | 1개 |
| 헤더 처리 시간 | 1초이며, 서버가 주기적으로 검사합니다. |
| 요청 처리 시간 및 소켓 유휴 시간 | 2초 |

한도를 소진하면 무제한 대기열을 만들지 않고 HTTP 429를 반환합니다.
본문 크기를 초과하면 HTTP 413을 반환합니다.
함정 본문 처리 시간을 초과하면 HTTP 408을 반환합니다.
애플리케이션 응답에서 캐시를 비활성화합니다.
증명 검증 전에 만료를 확인하며, 요청이 없어도 주기적으로 만료 상태를 정리합니다.
비활성화와 종료 시 타이머와 함정 상태를 삭제합니다.

## 범위와 실행 근거

이 예제는 단일 프로세스 학습용이며, 운영 보안 경계가 아닙니다.
인증, 영구 저장소, 복제본 조정, 실제 애플리케이션 통합은 포함하지 않습니다.
재시작하면 모든 증명과 이벤트를 삭제합니다.
정상 엔드포인트와 함정은 서버와 운영체제 자원을 공유합니다.
테스트는 일반적인 서비스 거부 공격에 대한 내성을 입증하지 않습니다.
운영 환경 활성화에는 별도의 검토와 승인이 필요합니다.

테스트는 정상 사용, 기본 비활성화, 재전송, 동시성, origin 검사, 만료, 자원 한도, 저장 실패, 연결 해제, 비활성화, 정리를 검증합니다.
검증한 함정 포화 상태와 저장 실패 상황에서도 정상 엔드포인트가 동작합니다.
모든 데이터는 합성 데이터입니다.

2026년 11월 2일 격리 실행에서는 준비된 `node:22.14.0-alpine` 이미지를 사용했습니다.
고정 이미지 식별자는 다음과 같습니다.

```text
node@sha256:9bef0ef1e268f60627da9ba7d7605e8831d5b56ad07487d24d1aa386336d1944
```

이 식별자는 테스트에 사용한 이미지를 기록하며, 현재 보안 권장 버전을 의미하지 않습니다.
최신 보안 권고 점검은 이 예제의 범위에 포함하지 않습니다.
원시 실행 로그는 공개 예제에 포함하지 않습니다.
