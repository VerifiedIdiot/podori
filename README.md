# podori

**함정부터 격리 검증까지, 쓰던 AI 에이전트로.**

한국어 안내 | [English](README.en.md) · `1.1.0`

podori(포돌이)는 평소 쓰는 AI 코딩 에이전트에 보안 점검과 수정, 테스트를 맡기는 스킬 모음입니다. 앱에 맞는 함정을 구현하고, 컨테이너·gVisor·Kata 중에서 고른 격리 환경에서 실행 검증을 돕습니다.

[내 프로젝트에서 시작하기](#내-프로젝트에서-시작하기) · [실행 예제 살펴보기](examples/trap/README.md)

## 문제를 찾고 고친 뒤, 정상 동작까지

권한 검사와 입력 검증의 허점을 살펴보고, 근거가 확인된 문제를 프로젝트 컨벤션에 맞춰 고칩니다. 고치기 전에 실패하는 테스트를 먼저 만들고, 고친 뒤 같은 테스트가 통과하는지와 기존 기능이 그대로인지를 함께 확인합니다.

결과는 정해진 양식의 기록 한 장으로 남습니다. 어떤 경계를 살폈는지, 무엇을 고쳤는지, 테스트가 수정 전후에 어떻게 달라졌는지가 매번 같은 자리에 있습니다.

코드를 바꾸지 않는 점검만 맡길 수도 있습니다.

## 수상한 접근을 찾아, 필요한 대응으로

정상 사용자는 찾을 일이 없는 가짜 API와 미끼 정보. `podori-trap`은 앱 구조에 맞는 함정을 만들고, 그곳에서 확인한 접근을 기록하도록 안내합니다.

기록에 이어, 앱의 운영 정책에 맞춘 대응까지 구현하도록 요청할 수 있습니다.

| 활용 | 구현할 수 있는 기능 |
|---|---|
| 미끼 API의 반복 접근 확인 | 관찰 목록과 접근 기록 |
| 확인된 탐지 이벤트 전달 | 운영자 알림 연동 |
| 근거가 확인된 접근 제한 | 일시 차단 |
| 차단 사유와 기간 관리 | 블랙리스트·만료·수동 해제 |

함정은 꺼진 상태로 만들어 두고, 켜는 시점은 직접 정합니다. 차단은 요청 주체를 확인할 근거와 승인한 정책이 있을 때 적용합니다.

## 실행 검증은 세 가지 격리 중 하나로

검증 코드를 어디서 돌릴지는 호스트에 맞춰 고릅니다. 표에서 아래로 갈수록 앱에 노출되는 호스트 커널의 범위가 줄어듭니다.

| 런타임 | 격리 방식 | 호스트 |
|---|---|---|
| `runc` | 컨테이너. 호스트 커널을 공유하고 namespace·cgroup·seccomp로 가둡니다 | Linux, macOS |
| `runsc` (gVisor) | 커널 가상화. 앱의 시스템 콜을 사용자 공간 커널이 대신 처리합니다 | Linux |
| `kata` (Kata Containers) | 하드웨어 가상화. 실험마다 전용 게스트 커널을 가진 microVM을 띄웁니다 | KVM을 쓰는 Linux |

세 런타임 모두 네트워크 차단, non-root, 읽기 전용 파일시스템을 똑같이 적용합니다. 실행할 때마다 격리 상태를 실제 컨테이너에서 확인합니다. **검증 코드를 실행하는 호스트 OS에 보호 계층을 더하는 방식입니다.**

podori의 선택형 로컬 MCP가 동봉한 샘플 앱을 격리해 실행하고, 수정 전후의 동작을 비교합니다. 기본값은 `runc`이며, `runsc`와 `kata`는 준비할 때 고릅니다.

함정 구현과 일반 보안 점검은 MCP 없이 시작할 수 있습니다. 격리 실행이 필요할 때 [샌드박스 안내](mcp/README.md)를 따라 준비하세요.

## 코드와 테스트로 확인하세요

**공개 함정 예제는 22개 HTTP 테스트를 통과했습니다.** 탐지 기록이 남는지, 같은 요청을 재사용할 수 없는지, 정상 기능이 유지되는지를 직접 확인할 수 있습니다.

[예제 코드와 실행 방법](examples/trap/README.md) · [샌드박스 CI](https://github.com/VerifiedIdiot/podori/actions/workflows/sandbox.yml)

예제는 탐지 기록까지 구현한 독립 데모이며 로컬 Docker의 `runc`에서 테스트했습니다. 샌드박스 CI는 `runc`와 gVisor를 Linux AMD64·ARM64에서, Kata를 Linux AMD64에서 실행합니다.

## 내 프로젝트에서 시작하기

릴리스 태그 `v1.1.0`에서 필요한 스킬 폴더 **전체**를 에이전트의 스킬 경로에 복사한 뒤, 대상 프로젝트에서 스킬을 호출하세요. 함정부터 시작하려면 `skills/podori-trap/`을 설치합니다.

```text
/podori-trap
```

기본 보안 점검과 수정부터 맡기려면 `skills/podori/`을 설치하고 호출하세요.

```text
/podori
```

각 스킬은 독립적으로 사용합니다. 필요한 작업만 골라 맡기세요.

| 원하는 작업 | 설치할 스킬 |
|---|---|
| 앱 맞춤 함정과 대응 구현 | [podori-trap](skills/podori-trap/SKILL.md) |
| 컨테이너·gVisor·Kata 샌드박스에서 샘플 앱 검증 | [podori-sandbox](skills/podori-sandbox/SKILL.md) |
| 보안 문제 점검·수정·테스트 | [podori](skills/podori/SKILL.md) |
| 패키지·컨테이너 이미지의 출처와 위험 점검 | [podori-doubt](skills/podori-doubt/SKILL.md) |
| 전자정부프레임워크 보안 기준 점검 | [podori-egov](skills/podori-egov/README.md) |

설치 위치와 호출 방식은 에이전트의 안내를 따릅니다. `podori-sandbox`에는 별도의 로컬 MCP 설정과 실행 승인이 필요합니다.
