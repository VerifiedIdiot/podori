# podori

**함정부터 격리 검증까지, 쓰던 AI 에이전트로.**

한국어 안내 | [English](README.en.md) · `1.0.0`

podori(포돌이)는 평소 쓰는 AI 코딩 에이전트에 보안 점검과 수정, 테스트를 맡기는 스킬 모음입니다. 앱에 맞는 함정을 구현하고, gVisor로 격리한 환경에서 실행 검증을 할 수 있도록 돕습니다.

[내 프로젝트에서 시작하기](#내-프로젝트에서-시작하기) · [실행 예제 살펴보기](examples/trap/README.md)

## 문제를 찾고 고친 뒤, 정상 동작까지

권한 검사나 입력값 처리의 허점을 살펴보고, 근거가 확인된 문제를 프로젝트 방식에 맞춰 고칩니다. 수정 뒤에는 보안 문제가 해결됐는지와 정상 기능이 유지되는지를 함께 테스트합니다. 확인한 결과와 남은 일도 구분해 전달합니다.

코드를 바꾸지 않는 점검만 맡길 수도 있습니다.

## 수상한 접근을 찾아, 필요한 대응으로

정상 사용자는 찾을 일이 없는 가짜 API와 미끼 정보. `podori-trap`은 앱 구조에 맞는 함정을 만들고, 그곳에서 확인한 접근을 기록하도록 안내합니다.

기록을 모으는 데서 끝낼 필요는 없습니다. 앱의 운영 정책에 맞춰 대응까지 구현하도록 요청할 수 있습니다.

| 활용 | 구현할 수 있는 기능 |
|---|---|
| 미끼 API의 반복 접근 확인 | 관찰 목록과 접근 기록 |
| 확인된 탐지 이벤트 전달 | 운영자 알림 연동 |
| 근거가 확인된 접근 제한 | 일시 차단 |
| 차단 사유와 기간 관리 | 블랙리스트·만료·수동 해제 |

함정은 기본적으로 꺼진 상태로 만듭니다. 차단은 단순 조회가 아니라 요청 주체를 확인할 근거와 승인한 정책에 따라 적용합니다.

## 실행 검증은 gVisor 안에서

일반 Docker 컨테이너는 호스트 OS의 커널을 공유합니다. gVisor는 앱과 호스트 커널 사이에 별도의 커널 계층을 두어, 앱이 호스트 커널을 직접 공격할 수 있는 범위를 줄입니다. **검증 코드를 실행하는 호스트 OS에 보호 계층을 더하는 방식입니다.**

podori의 선택형 로컬 MCP는 Linux에서 gVisor를 지원합니다. 동봉한 샘플 앱을 격리해 실행하고, 수정 전후의 동작을 비교합니다.

함정 구현과 일반 보안 점검은 MCP 없이 시작할 수 있습니다. 격리 실행이 필요할 때 [샌드박스 안내](mcp/README.md)를 따라 준비하세요.

## 코드와 테스트로 확인하세요

**공개 함정 예제는 22개 HTTP 테스트를 통과했습니다.** 탐지 기록이 남는지, 같은 요청을 재사용할 수 없는지, 정상 기능이 유지되는지를 직접 확인할 수 있습니다.

[예제 코드와 실행 방법](examples/trap/README.md) · [gVisor 샌드박스 CI](https://github.com/VerifiedIdiot/podori/actions/workflows/sandbox.yml)

예제는 탐지 기록까지 구현한 독립 데모이며 로컬 Docker의 `runc`에서 시험했습니다. gVisor 실행은 Linux AMD64·ARM64의 별도 CI에서 검증했습니다.

## 내 프로젝트에서 시작하기

릴리스 태그 `v1.0.0`에서 필요한 스킬 폴더 **전체**를 에이전트의 스킬 경로에 복사한 뒤, 대상 프로젝트에서 스킬을 호출하세요. 함정부터 시작하려면 `skills/podori-trap/`을 설치합니다.

```text
/podori-trap
```

기본 보안 점검과 수정부터 맡기려면 `skills/podori/`을 설치하고 호출하세요.

```text
/podori
```

각 스킬은 독립적으로 사용합니다. 필요한 작업만 골라 맡기세요.

| 원하는 작업 | 설치할 스킬 |
|---|---|
| 앱 맞춤 함정과 대응 구현 | [podori-trap](skills/podori-trap/SKILL.md) |
| gVisor 등 샌드박스에서 샘플 앱 검증 | [podori-wreck](skills/podori-wreck/SKILL.md) |
| 보안 문제 점검·수정·테스트 | [podori](skills/podori/SKILL.md) |
| 패키지·컨테이너 이미지의 출처와 위험 점검 | [podori-doubt](skills/podori-doubt/SKILL.md) |
| 전자정부프레임워크 보안 기준 점검 | [podori-egov](skills/podori-egov/README.md) |

설치 위치와 호출 방식은 에이전트의 안내를 따릅니다. `podori-wreck`에는 별도의 로컬 MCP 설정과 실행 승인이 필요합니다.
